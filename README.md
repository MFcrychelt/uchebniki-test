# Школьная библиотека — учёт учебников

PWA для учёта выдачи и возврата учебников школьной библиотеки: QR-коды
учеников, сканирование штрихкодов (ISBN) с обложек и цифровые чек-листы
выдачи вместо ручной отметки.

## Стек

| Слой | Технология |
| --- | --- |
| Фреймворк | Next.js 16 (App Router) + TypeScript |
| База данных | PostgreSQL (≥ 15) |
| ORM | **Prisma 8** (`@prisma/orm-postgres`) — contract-first, клиент на TS + `pg`, без нативных бинарников |
| Стили / UI | Tailwind CSS 4 + shadcn/ui-компоненты |
| PWA / Service Worker | @serwist/next (precacche + runtime caching, офлайн-страница) |
| QR-сканер | html5-qrcode (QR учеников + EAN/Code-128/Code-39 — ISBN) |
| QR-генерация | qrcode.react (личный QR ученика) |

## Бизнес-процесс

1. **Сбор и подпись.** Ученик берёт учебники из «башен» по списку из своего
   личного кабинета и вписывает фамилию в конце каждой книги (как раньше).
2. **Идентификация.** Ученик показывает личный QR-код со смартфона;
   библиотекарь сканирует его — открывается профиль с чек-боксами по
   предметам.
3. **Выдача (электронные галочки).** Библиотекарь сканирует ISBN с обложек —
   в БД фиксируется «Иванов получил Математику и Физику». Или просто отмечает
   чекбоксы / «Выдать всё».
4. **Возврат.** В конце года библиотекарь видит долги, проверяет подпись в
   конце книги и снимает её с цифрового профиля.

## Роли

- **Ученик** (`/student`) — личный кабинет: логин и пароль для будущих
  входов (на видном месте, с кнопкой «копировать»), QR-код для
  библиотекаря, выданные учебники, история, заявки на книги
  (попросить / отменить). **Список учеников никому не показывается**.
  Вход — тремя способами (см. «Magic links» ниже):
  1. **Одноразовая ссылка от учителя** (`/invite/<токен>` из мессенджера
     или по QR-карте): один клик — и кабинет, сессия на 30 дней.
  2. **Логин + пароль** (форма на `/student`; выдаёт система).
  3. **Личный QR** (сканер приложения или камера телефона: QR кодирует
     `/student?qr=<токен>`; если камеры нет — ручной ввод кода с карточки).
  Кабинет запоминается в localStorage, есть кнопка «Выйти» (сбрасывает
  и localStorage, и cookie-ессию).
- **Библиотекарь** (`/librarian`, вход) — скан QR ученика (без камеры —
  ручной ввод кода с карточки), скан ISBN,
  чек-лист класса (с бейджами наличия по тиражу), ручное внесение
  ISBN, «Выдать всё», возврат, вкладки «Долги», «Журнал», «Каталог»,
  «Статистика», «Отчёт», «Переучёт», «Заявки».
- **Администратор** (`/admin`, вход) — классы, ученики (с автогенерацией
  QR-токена, логина/пароля и magic link), вкладка «Ссылки» (раздача
  одноразовых ссылок: копирование + печать QR), каталог учебников,
  привязка книг к классам, массовый импорт (Excel/CSV), журнал действий
  (аудит), вкладка «Обновления» (саммоуфр сайта, см. ниже).

### Авторизация персонала

- Вход: `/login` → `POST /api/auth/login { login, password }`.
  Сессия — подписанный HMAC-SHA256 токен в httpOnly-cookie `session`
  (12 часов, stateless — сессий в БД нет). Секрет — `SESSION_SECRET`
  в `.env` (не коммитится).
- Пароли — scrypt (соль в хеше), храним в `users.password_hash`.
- **Роли**: `STUDENT` (свой кабинет: magic link / логин+пароль / личный
  QR), `LIBRARIAN`, `ADMIN`.
  - `/librarian` — оба сотрудника (выдача/возврат/отчёты/CSV).
  - `/admin` — только `ADMIN` (`requireAdmin`); вошедший библиотекарь
    редиректится в `/librarian`.
  - API: операции с книгами и отчёты — `staffUser()` (401);
    админ-CRUD (классы/ученики/книги) — `adminGuard()` (401/403);
    кабинет ученика — `studentUser()` по cookie (401).
- Открыто: кабинет ученика по личному QR-ключу (`/student?qr=…`,
  `GET /api/student/qr/:token`, заявки ученика), одноразовые ссылки
  `/invite/<токен>` (логин ученика) и каталоги (`GET /api/classes|books`).
  **Список учеников** (`GET /api/students`) и карточки по id — только
  персонал: список имён не публичен.
- **Сессия ученика** — тот же HMAC-cookie `session`, но на **30 дней**
  («зашёл по ссылке от учителя и забыл про вход»); персонала — 12 ч.
  Логин/пароль ученика генерирует система; пароль в БД — AES-256-GCM
  (`users.password_enc`), чтобы показывать его в кабинете.

### Magic links (вход ученика, M23)

1. **Подготовка**: админ импортирует класс (Excel `.xlsx` или CSV,
   вкладка «Импорт») — каждому ученику автоматически выдаются логин
   (фамилия в латинице + 4 случайных символа, `ivanov-8k2m`), пароль
   (8 символов), QR-токен и **одноразовая ссылка** `/invite/<токен>`.
   Учеников без ссылок (созданных ранее) догенерит кнопка
   «Создать для всех без ссылок» во вкладке **«Ссылки»**.
2. **Раздача**: учитель копирует ссылки в мессенджер
   («Скопировать все активные») или печатает QR-карты
   (`/print/invite-qr`, 2×N, использованные — серые).
3. **Вход**: ученик кликает по ссылке с телефона —
   `/invite/<токен>` → `GET /api/invite/<токен>` атомарно расходует
   токен (`users.invite_used_at`), ставит httpOnly-cookie сессии
   (30 дней) и редиректит в `/student`. Повторно ссылка не работает
   (→ страница «Ссылка не подошла»).
4. **Дальше**: ученик «всегда авторизован» на устройстве до «Выйти»;
   с любого другого устройства — по логину/паролю, которые видны в
   кабинете (`GET /api/student/me/credentials`, только по сессии
   ученика; по чужому QR-токену пароль не отдаётся).
- Выдача фиксирует, кто её произвёл (`Loan.librarianId`) — видно в журнале.
- Демо-доступ (ставит `npm run seed`): библиотекарь **librarian / lib123**,
  администратор **admin / admin123**.

### Печать (физическая часть процесса)

- `/print/class-list?classId=…` — печатный список учебников класса
  (таблица: предмет / учебник / ISBN / отметка + строки подписей).
- `/print/labels` — лист этикеток для книг каталога (2×N, название,
  предмет, ISBN).
- `/print/qr-cards` — QR-карточки учеников (2×N, QR + ФИО + класс):
  все классы и `?classId=` — один класс (только персонал, список
  имён не публичен), `?qr=` — «моя карточка» из кабинета по QR-ключу.
- `/print/invite-qr` — QR-карты с **magic links** `/invite/<токен>`
  для раздачи на классном часу (только персонал; использованные
  ссылки — серые, с пометкой).
- `/print/loss-act` — акт списания (утери) учебников: `?from=&to=`
  (по дате утери), таблица + подписи; кнопка — в «Журнале».
- `/print/report?from=&to=` — отчёт о работе библиотеки за период
  (итоги, по предметам/классам, топ-10 книг, снимок долгов) +
  подписи; кнопка «Печать» — во вкладке «Отчёт».
- Кнопки: в админке — иконки QR и принтера у каждого класса, «Печать
  этикеток» во вкладке «Книги»; в кабинете ученика — «Печать моей
  карточки». Страницы открытые, кроме списков учеников (QR-карточки
  всех классов — только персонал; «моя карточка» — по QR-ключу);
  тулбар «Печать/Закрыть» скрывается при печати (`@media print`).

### Офлайн-очередь (PWA)

При обрыве сети библиотекарь продолжает работать: неудавшиеся операции
(выдать / вернуть / «утеряна») сохраняются в `localStorage` и
автоматически отправляются при появлении соединения.

- `src/lib/offline-queue.ts` — чистое ядро (тесты: `npm run test:queue`):
  FIFO-прогон, 2xx — принято; **409/404 — «уже обработано» (повторный
  запрос после обрыва или с другого устройства) — списывается**;
  400/401/5xx — конфликт, до 5 попыток, затем «заморозка» (ручное
  решение); сетевой сбой — стоп, попытки не сжигаются.
- `src/lib/offline-queue-browser.ts` — localStorage + fetch; события
  `uchebniki:queue-changed` / `uchebniki:data-changed` (вьюшки
  перечитывают данные после синхронизации).
- `QueuePanel` (в панели библиотекаря): индикатор «нет сети», список
  операций, «Синхронизировать», удаление операции, «убрать неудачные».
- Покрыты операции с книгами (выдача/возврат/утеряна); CRUD админки
  в очередь не идёт.

### Отчёт для директора

Сводка работы библиотеки **за период** — в отличие от «Статистики»
(снимок «на сегодня»): потоки считаются по датам событий, не по датам
записи. Вкладка «Отчёт» в `/librarian` + печатный документ
`/print/report?from=&to=` (с подписями «составил(а) / согласовал(а)»)
+ CSV `/api/exports/summary`.

- Период: `?from=&to=` (даты, включительно; без параметров — за всё
  время). Пресеты в UI: «Текущий год», «Текущий месяц», «За всё время».
- **Итоги за период**: выдано (по `issuedAt`), возвращено (по
  `returnedAt`, только RETURNED), утеряно (по `lostAt`, только LOST),
  компенсировано (по `compensatedAt`), заявки (создано по `createdAt`;
  выполнено/отклонено по `handledAt`).
- **Снимок «на сейчас»** (не зависит от периода): сейчас выдано
  (ISSUED), ученики с долгами.
- Разбивки за период: по предметам и по классам (выдано / возвращено /
  утеряно) + топ-10 самых выдаваемых учебников.
- `GET /api/reports/summary?from=&to=` (⭐) — JSON того же отчёта
  (`totals`, `bySubject`, `byClass`, `topBooks`, `requests`).

### Экспорт в CSV (для школьного офиса)

- Кнопка «CSV» во вкладках «Долги», «Журнал» и «Отчёт» — выгружает
  текущий фильтр: `/api/exports/debts`, `/api/exports/journal`,
  `/api/exports/summary` (отчёт — плоская таблица «раздел;позиция;
  значения»).
- Формат: разделитель `;`, BOM (кириллица в Excel), даты `дд.мм.гггг`;
  у журнала — колонка «Выдал(а)» (аудит).

### Инвентаризация (переучёт)

Физический контроль учёта: библиотекарь сканирует штрихкоды книг, лежащих
в «башнях», приложение сверяет сканы с каталогом и активными выдачами
(вкладка «Переучёт» в `/librarian`).

- Сессия сканов живёт в браузере (localStorage) — можно прерывать и
  продолжать; запросы: `POST /api/stocktake { isbn: string[], classId? }`
  (stateless, отчёт на лету). Класс ограничивает охват его учебниками.
- Счётная логика с тиражами (см. «Тиражи»): в башне ожидается
  `copies − выдано` копий каждой книги, сканы сравниваются с этим
  числом, а не с фактом «есть/нет».
- Отчёт (5 секций):
  - **Выданы и не найдены в башне (проверка)** — справка по выдачам;
    по строке кнопка «Утеряна» (закрывает выдачу статусом LOST);
  - **Найдены в башне, но в учёте «выданы»** — возврат не зарегистрирован
    (показаны последние «лишние» выдачи); кнопка «Возврат»
    (PUT `/api/loans/:id/return`);
  - **В учёте «в библиотеке», но не найдены** — с бейджем «не хватает N
    из M» (копий, ожидавшихся в башне);
  - **Сканов больше, чем копий в каталоге** — каталог не учитывает копии;
  - **Не в каталоге** — ISBN с количеством сканов (кандидаты в каталог).
- ISBN скана нормализуется (дефисы/пробелы) — совпадает с логикой
  импорта; повторные сканы считаются (с тиражами это нормальные разные
  копии), в отчёт уникальные ISBN идут со счётчиком повторов.
- Ядро — чистая функция `buildStocktakeReport` (`src/lib/stocktake.ts`),
  тесты: `npm run test:stocktake` (26 кейсов: тиражи + списание).
- Офлайн: сканы накапливаются локально; расчёт отчёта и действия по
  строкам — при сети (сбои LOST/возврат попадают в офлайн-очередь,
  как и в «Долгах»).

### Каталог и карточка учебника

Вкладка «Каталог» у библиотекаря: поиск по каталогу (название, предмет
или ISBN, без учёта регистра) и карточка учебника по клику.

- `GET /api/books?q=…` — поиск; без `q` — весь каталог. Каждая книга
  несёт `available` — сколько ещё можно выдать (тираж минус выдачи).
- `GET /api/books/:id` (⭐) — карточка: данные (включая «экземпляров /
  в наличии»), классы, последние выдачи (кто сейчас держит + история,
  максимум 10), ожидающие заявки со ссылкой на вкладку «Заявки».

Поиск делается на стороне приложения, а не через SQL `ilike`: в
dev-БД (embedded Postgres) коллация `C`, и `lower()` в SQL не
конвертирует кириллицу — искомое слово с маленькой буквы не находилось.

### Тиражи (несколько экземпляров одной книги)

У каждой книги — число физических экземпляров в фонде (`Book.copies`,
по умолчанию 1). Система считает остаток: **в наличии = copies −
выдано − списано** (утерянные) и не даёт выдать «больше, чем есть».

- **Выдача** (`POST /api/loans`): если все экземпляры выданы — 409
  «Все экземпляры книги выданы (N шт.)». Чек-лист выдачи показывает
  бейдж «нет в наличии» / «N в наличии»; «Выдать всё» пропускает
  книги без остатка и отчитывается в сводке.
- **Заявки (M14)**: «Выдать» по заявке на книгу без остатка — 409,
  заявка остаётся в очереди (выполнится, когда кто-то вернёт копию).
  Ученик в кабинете видит «нет в наличии — выдадим, когда появится»
  и может поставить заявку в ожидание.
- **Каталог и карточка (M15)**: список показывает «N в наличии» /
  «нет в наличии», карточка — «экземпляров: N [· утеряно: K] · в
  наличии: M».
- **Списание (утеря).** Копия не появляется «ниоткуда»: если книга
  утеряна (выдача закрыта статусом `LOST` — кнопка «Утеряна» в
  «Долгах» и отчёте инвентаризации), она **вычитается из остатка**:
  `в наличии = copies − выдано − списано`. Долг по такой книге
  закрывается (не числится в «Долгах»), в кабинете ученика — в
  «Истории» с пометкой «Утеряно». Чтобы фонд снова пополнился —
  админ увеличивает тираж (покупка замены). Демо: у Петрова
  (8-А) «Литература, 8 класс» утрачена.
- **Инвентаризация (M12)** учитывает тиражи и списание: ожидается в
  башне `copies − выдано − списано` копий; отчёт находит «не
  хватает N из M», «выданные, но нашлись в башне» (последние выдачи)
  и блок «сканов больше, чем копий в каталоге». Повторный скан той же
  книги — нормальное дело (это ещё одна копия), а не ошибка.
- **Админ**: тираж задаётся при создании книги и меняется в списке
  (PATCH `/api/books/:id` ⭐A, аудит `book.update`); нельзя
  уменьшить ниже «выдано + списано».

### Акт списания и компенсация

Завершает цикл утраченной книги: утерянное (LOST) — долг, который
закрывается компенсацией (выдана замена / произведена покупка).

- **Пометка «утеряна»** пишет `lostAt` (дата утери) — она же дата
  в акте.
- **Компенсация** — `POST /api/loans/:id/compensate` (⭐; только
  LOST, 409 если уже отмечена; фиксирует `compensatedAt` + кто
  отметил), `DELETE` — снять отметку. Операции пишутся в аудит
  (`loan.compensate` / `loan.compensate.cancel`).
- **Журнал**: по LOST-строкам — дата утери, отметка «компенсирована»
  (кто, когда) и кнопки «Компенсирована» / снять. CSV-экспорт
  журнала — колонка «Компенсирована».
- **Акт списания** — печатный документ `/print/loss-act?from=&to=`:
  все утерянные за период (ученик, класс, учебник, ISBN, дата
  утери, компенсация), подписи «составил(а) / согласовал(а)».
  Кнопка «Акт списания» — в журнале (берёт текущие даты фильтра).
- Кабинет ученика: утерянная в «Истории» получает строку
  «Компенсирована: …» после закрытия долга.
- Демо: «Литература, 8 класс» у Петрова (8-А) утрачена,
  компенсация не отмечена — готовый сценарий.

### Заявка на учебник

Ученик из личного кабинета просит книгу из списка своего класса;
библиотекарь видит очередь и выдаёт (или отказывает) в один клик.

- Ученик: в кабинете — секция «Запрошенные учебники»: у каждой книги
  кнопки «Попросить» / «Ожидает · отменить» / «Выдана». Активных заявок
  на одну книгу — не более одной (409). Идентификация — QR-токен
  (`/api/student/qr/:token/requests`), как во всём ученическом flow.
- Библиотекарь: вкладка «Заявки» — очередь PENDING (ученик, книга,
  дата, комментарий) с кнопками «Выдать» / «Отказать» + блок
  «Недавно выполненные».
- «Выдать» создаёт выдачу (`Loan`, фиксирует, кто выдал) и закрывает
  заявку со статусом `ISSUED`. Если книга уже выдана этому ученику —
  выдача не дублируется (`alreadyIssued: true`), заявка просто
  закрывается. Если экземпляров нет — 409, заявка остаётся в очереди
  (см. «Тиражи»). «Отказать» — статус `DECLINED`.
- `GET /api/requests` (⭐) — `?status=PENDING|ISSUED|DECLINED`,
  `?limit=`. Операции — `POST /api/requests/:id/fulfill|decline` (⭐),
  пишем в аудит (`request.fulfill`, `request.decline`).

### Импорт из Excel/CSV (начало учебного года)

Массовое создание учеников и учебников — замыкает круг с экспортом.
Только ADMIN (вкладка «Импорт» в `/admin`; API — `adminGuard`,
библиотекарь получает 403).

- Ученики: **Excel `.xlsx`** (SheetJS, серверный разбор) или CSV.
  Файл читается в браузере и отправляется JSON-телом
  `{ xlsxBase64, dryRun }` или `{ csv, dryRun }` — multipart не
  используется. Первый лист, заголовок «Фамилия/Имя/Класс»
  (порядок столбцов не важен; без заголовка — по порядку).
- Шаблоны: «Ученики» — `Фамилия;Имя;Класс` (класс опционален),
  «Учебники» — `ISBN;Название;Предмет;Класс` (класс — опциональная
  ссылка). Кнопка «Скачать шаблон» отдаёт пример с BOM.
- Новому ученику автоматически выдаются QR-токен, **логин/пароль и
  одноразовая ссылка для входа** (magic link, см. выше) — раздача:
  вкладка «Ссылки».
- Разбор (`parseCsv` в `src/lib/csv.ts`, тесты `npm run test:csv`):
  автоопределение разделителя `;`/`,` по первой строке, кавычки
  (включая `""` внутри), CRLF/LF, BOM, пустые строки, trim ячеек.
- Семантика:
  - классы, которых нет, создаются автоматически (сравнение по имени,
    регистр не важен);
  - дубли пропущены: ученик — по `Фамилия+Имя+класс`, книга — по ISBN
    (сравнение после удаления дефисов и пробелов);
  - ученикам выдаётся уникальный `qrToken` (для QR-карточки);
  - ссылка «книга ↔ класс» создаётся только при реальном импорте;
  - `dryRun: true` — только отчёт (`total/created/skipped/newClasses/
    links` + ошибки по строкам) без записи в БД; кнопка «Проверить».
- Ответ: `{ dryRun, total, created, skipped, newClasses, links,
  errors: [{ row, message }] }` — в UI сводка и первые 10 ошибок.

### Журнал действий (аудит)

Отдельно от журнала выдач — кто из персонала менял справочники. Покрывает
создание/удаление классов, учеников и книг, привязку книг к классам,
массовые импорты (с итогами), входы/выходы. Только ADMIN.

- Хранится в `audit_log`: время, исполнитель (`actorId` + денормализованные
  `actorName`/`actorRole` — запись сохраняет смысл после удаления
  сотрудника), действие (`class.create`, `student.delete`, `import.books`,
  `auth.login`, …), сущность и метаданные (имя, ISBN, счётчики) в JSON.
- Запись идёт из API-роутов после успешной мутации
  (`logAudit()` в `src/lib/audit.ts`); сбой аудита не роняет основной flow.
- `GET /api/audit` (⭐A) — фильтры `?entity=&action=&from=&to=&limit=`
  (лимит до 500), сортировка по убыванию времени.
- UI: вкладка «Аудит» в `/admin` — раздел/период, таблица «когда · сущность ·
  действие (метаданные) · кто».

### Обновления сайта (саммоуфр, вкладка «Обновления» в `/admin`)

Сценарий: сайт развёрнут **на сервере школы**, а разработчик пушит код в
GitHub **из дома**. Чтобы обходить по школе с флешкой не нужно — обновление
запускается прямо из админки:

1. Разработчик пушит изменения в ветку, на которой развёрнут сервер.
2. В `/admin` → вкладка «Обновления»: видна **текущая версия** (git HEAD:
   хеш, subject, ветка, дата) и **доступные обновления** (кнопка
   «Проверить обновления» делает `git fetch` и показывает список новых
   коммитов).
3. Кнопка «Обновить сайт» (подтверждение **паролем администратора** —
   страховка от перехваченной сессии) запускает пайплайн:
   `git pull --ff-only` → `npm ci` (только если менялся
   `package-lock.json`) → `npm run build` → **перезапуск сервера**.
   Прогресс по фазам виден в UI (опрос каждые 2 с); после перезапуска
   страница сама обновляется.

Перезапуск задаётся `RESTART_CMD` в `.env`:

- с надзирателем: `RESTART_CMD="pm2 restart school-library"` или
  `RESTART_CMD="systemctl restart school-library"`;
- без надзирателя: `RESTART_CMD="bash scripts/restart-server.sh"` —
  встроенный скрипт дожидается освобождения порта 3000 и поднимает
  новый `npm start` в отдельной сессии;
- не задана — процесс сам завершится, сервер поднимет надзиратель
  (pm2/systemd/docker `--restart`).

Доступ к GitHub с сервера: репозиторий **приватный**, поэтому на сервере
нужен git-доступ — либо SSH-ключ (добавить публичный ключ сервера в
deploy keys репозитория), либо токен в URL remote:
`git remote set-url origin https://<token>@github.com/MFcrychelt/uchebniki-project.git`.
UI показывает подсказку, если `git fetch` не удалось. Токены в URL не
попадают в интерфейс и логи (маскируются, `maskSecrets`).

Технически: `src/lib/update.ts` (статус + фоновая задача),
`GET /api/admin/update/status` (⭐A, `?refresh=1` — повторить fetch),
`POST /api/admin/update` (⭐A, `{ password }`). Ошибки предыдущего
обновления с хвостом лога видны во вкладке; запуск пишется в аудит
(`update.start`).

## Структура данных (prisma/schema.prisma)

- `User` — ученики и библиотекари, `qrToken` — уникальный токен для QR;
  у персонала — `login` (уникальный) + `passwordHash` (scrypt);
- `Class` — классы (например «8-А»);
- `Book` — каталог учебников, `isbn` уникален, `copies` — число
  физических экземпляров в фонде;
- `ClassBook` — связь «класс ↔ учебник» (ожидаемый список);
- `Loan` — выдача: ученик + книга + статус `ISSUED | RETURNED | LOST`
  (`LOST` = списана/утеряна — уменьшает остаток, см. «Тиражи» →
  «Списание»), время выдачи/возврата/утери (`lostAt`), кто выдал,
  компенсация утери (`compensatedAt` + кто отметил);
- `BookRequest` — заявка ученика на учебник: `PENDING | ISSUED |
  DECLINED`, комментарий, кто и когда обработал;
- `AuditLog` — журнал действий персонала (см. «Журнал действий»).

## Prisma 8: как устроено

- Контракт — `prisma/schema.prisma`; артефакты `prisma/schema.json` и
  `prisma/schema.d.ts` генерируются `prisma contract emit` (в .gitignore).
- Подключение — `prisma.config.ts` (`definePrismaConfig` + `ormConfig`),
  `DATABASE_URL` читается из `.env`.
- Клиент — `src/lib/prisma.ts`: `postgres<Contract>({ contractJson, url })`,
  один экземпляр на процесс. Запросы: `db.orm.public.User.where(...).all()`,
  `.include('loans', (l) => l.include('book'))`, транзакции — `db.transaction(...)`.
- Времена (`timestamptz`) читаются/пишутся через `Temporal`: в Node 22
  требуется полифилл `@js-temporal/polyfill` — он подключается в
  `src/lib/temporal-polyfill.ts` (импортируется первым в `src/lib/prisma.ts`).
- Агенты-доки по установленной версии ORM: `npx prisma skills sync`.

> **Важно про версии (lockstep).** CLI `prisma` 8.0.0-rc.11 эммитит контракт
> своим toolchain'ом **rc.8**, поэтому `@prisma/orm-postgres` пинится на
> **8.0.0-rc.8** — версии эмиттера и рантайма должны совпадать, иначе
> типизация `postgres<Contract>` не сойдётся. При обновлении CLI сверяйте
> `@prisma/orm-toolchain` в зависимостях CLI и ставьте ту же версию ORM.

## PWA

- `serwist.ts` — service worker (precache + runtime-стратегии
  `defaultCache`, fallback на `/~offline`).
- `next.config.ts` — `withSerwistInit` (`swSrc: serwist.ts`,
  `swDest: public/sw.js`, `cacheOnNavigation`), выключен в dev.
- `public/manifest.json` + иконки `icon-192/512.png` (генерируются
  `scripts/generate-icons.mjs`).
- SW регистрируется в production-сборке; в dev — нет (иначе кэш мешает).
  Регистрация — через лёгкий stub: плагин `@serwist/next` вставляет в
  каждый initial-бандл `sw-entry.mjs`, который статически тянет всю
  клиентскую библиотеку `@serwist/window` (~245 КБ). `next.config.ts`
  подменяет её webpack-alias'ом на `src/lib/sw-client.ts` — нативный
  `navigator.serviceWorker.register()` (кэш-логика и так живёт в `sw.js`).
- Офлайн: статические страницы и API-ответы (GET) кэшируются, есть
  offline-страница `/~offline`.

## Производительность (мобильные)

Система открывается с телефона на слабом канале, поэтому тяжёлое грузится
лениво:

- **Сканер камеры** (`html5-qrcode` + декодеры zxing, ~400 КБ) — динамический
  `import()` в `@/components/scanner`: чанк появляется только когда
  библиотекарь реально нажал «Сканировать» и открыл камеру. Форматы
  штрихкодов — в `src/lib/scanner-formats.ts` (числа enum'а, чтобы не тянуть
  библиотеку ради констант).
- **Вкладки панели библиотекаря** — `React.lazy` + `Suspense`: каждая
  вкладка (кроме дефолтной «Выдача») — отдельный чанк, грузится при первом
  открытии. Начальный бандл `/librarian` — только shell + «Выдача».
- **Service worker** — см. PWA: клиентский Workbox не попадает в initial-бандл.

Итог (production, без полифила старых браузеров): initial JS
`/student` ≈ 0.5 МБ (gzip ~0.15 МБ), `/librarian` ≈ 0.5 МБ; сканер и
вкладки добавляются по требованию.

Мобильный UX:

- Поля ввода — 16px на телефоне (`text-base sm:text-sm`): iOS Safari
  не зумит страницу при фокусе (автозум включается для шрифта < 16px).
- Кнопки — `touch-action: manipulation` (нет паузы двойного тапа).
- Чек-лист выдачи: тап по всей строке (название книги) переключает
  выдачу/возврат — не нужно бить в маленький чекбокс.
- Вкладки панели — горизонтальный скролл одним рядом (на 360px не
  ломаются в 2 ряда по 4).

## Замечания

- Учёт «подписи в книге» остаётся ручным (визуальная проверка библиотекаря) —
  приложение фиксирует только факт выдачи/возврата.
- Роль `ADMIN` — отдельная учётка для управления справочниками
  (`Role`-enum в схеме, `requireAdmin()`/`adminGuard()` в `src/lib/auth.ts`).
  Библиотекарь права администратора не имеет (403 / редирект).
- При удалении класса его ученики остаются без класса (`classId → NULL`):
  FK `users.class_id` — `ON DELETE SET NULL` (явно в схеме; если FK
  оказывается `NO ACTION` — пересоздать миграцией, см.
  `migrations/app/20260913T1946_fix_users_class_fk_set_null/`).

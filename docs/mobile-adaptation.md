# Телефон: Android и iOS — что сделано и как проверить

Документ описывает мобильную часть редизайна (ориентир — fermi.gg) и
содержит **процедуру проверки на реальном устройстве**. Быстрые проверки
вынесены в конец — их можно выполнить прямо в браузере телефона за 10 минут.

Два принципа, из которых выросли все правки:

1. **Практичность** — экран телефона это «один экран = одно действие».
   Главный жест всегда внизу, в зоне большого пальца; второстепенное уходит
   в сворачиваемые блоки; текст крупный, поля не прячутся под клавиатурой.
2. **Слабое устройство** — ничего лишнего, что стоит кадров: никаких
   веб-шрифтов, картинок-фонов, `backdrop-blur`, теней-на-каждой-строке и
   анимаций без смысла. Тяжёлые списки не раскладываются вне экрана.

## 1. Дизайн-система (что использовать дальше)

Типографика «без плаката»: `h1/h2` — вес 600 и лёгкое сжатие
(`--tracking-tight2: -0.011em`), микро-подписи `.eyebrow` — 12px/600 с
разрядкой 0.08em (было 11px/700/0.14em), заголовки карточек — 600. Веб-шрифтов
по-прежнему нет: меняем начертание, а не семейство, потому что загрузка
шрифта на слабом телефоне стоит дороже, чем «дизайнерский» облик.



Палитра нейтральная: холст `#f7f8fa`, текст `#1f2228`, карточки белые,
акцент — чернильный синий `#205eda`, панели — `#1e3a46`. Тёмная тема —
почти чёрный холодный графит: **фон `rgb(3 8 10)` = `#03080a`, карточки и
блоки `rgb(8 13 15)` = `#080d0f`**, всплывающие списки `rgb(11 17 20)`
(полшага выше карточки). Разница фон/карточка — 1.7% яркости, поэтому
граница здесь не декорация, а единственный разделитель: `--border` и
`--input` — белый с прозрачностью 16% и 26%; `--shadow-card` и
`--shadow-panel` в тёмной теме `none` (чёрная тень на чёрном не читается,
а перерисовка слоя остаётся). Тёплый подтон (hue 70) убрался не «для
красоты»: над таким фоном он уходил в грязь и спорил с синим акцентом.
Текст — `#f0f4f6` (17.7:1 на карточке), второстепенный — `#a0b1b9` (8.8:1).

Токены и утилиты лежат в `src/app/globals.css`; примитивы —
`src/components/ui/*`. Веб-шрифтов нет намеренно: стек системный
(`-apple-system, "Segoe UI", Roboto, ...`), поэтому текст появляется в
первом кадре и на iOS, и на Android.

| Токен | Зачем |
| --- | --- |
| `--background: oklch(0.978 0.003 260)` | светлый нейтральный холст (`#f7f8fa`): не белый «больничный» и не жёлтая «бумага» — карточка от фона отличается яркостью, а не оттенком |
| `--panel: oklch(0.33 0.04 228)` = `#1e3a46` | одна насыщенная панель на экран — носитель главного действия (приём из fermi.gg). Приглушённый «петроль» вместо тёмно-синего: спокойнее выглядит как рабочий инструмент и не спорит с синим акцентом |
| `--primary: oklch(0.52 0.2 262)` | единственный акцент: кнопки, ссылки, состояния «мы тут» |
| `--shadow-card` | одна статичная тень на карточку; нет теней на строках списка |
| `--radius: 1rem`, `--radius-panel: 1.5rem` | крупные радиусы панелей, умеренные у контролов |

Классы:

| Класс | Что даёт |
| --- | --- |
| `.panel`, `.panel-field`, `.panel-muted`, `.eyebrow`, `.num` | панель и её внутренние элементы (поле на белом 12% поверх цветного фона, микро-надпись, табличные моно-цифры) |
| `.dock` | липкая нижняя панель действия: `44px` + `padding-bottom: env(safe-area-inset-bottom)` |
| `.safe-t` `.safe-b` `.safe-x` | отступы в зоны выреза/полоски жестов |
| `.cv-rows`, `.cv-block` | `content-visibility: auto` — строки вне экрана не раскладываются и не рисуются (чек-лист выдачи, выбор ученика по классу, «Долги», список выданного у ученика; в «Журнале» приём был и раньше) |
| `.isolate-paint` | `isolation: isolate` на липких слоях: скролл не перерисовывает всё дерево |
| `.row-done`, `.checkbox-tick` | отмеченная строка выдачи (лёгкая зелёная подложка + галочка) |
| `.logo-tile`, `.logo-book` | «живой» знак библиотеки на экранах входа и на главной (transform + box-shadow на одном элементе) |
| `.sheet-in` | выезд снизу для шторок (все разделы, карточка учебника на телефоне) |
| `@media (pointer: coarse)` | `min-height: 2.75rem` (44px) для `button`, `[role=button]`, `summary`; «плотным» контролям — `data-tight` |
| `html[data-perf="lean"]` | ручной лёгкий режим: гасит анимации, тени и обложки книг |

Палитра статусов сознательно оставлена семантической (успех/предупреждение/
ошибка) — акцентный синий не конфликтует с «долгами» и «утерянными».

### Экран входа: эргономика для «очков и старого монитора»

Вход персонала (`src/app/login/page.tsx`) отделён от «лендингового» вида —
это рабочий инструмент, и требования к нему другие:

| Что | Зачем |
| --- | --- |
| `Input size="lg"` / `PasswordInput size="lg"` — 17px в поле, высота 48px | 16px — технический минимум (иначе iOS зумит); для чтения в очках и на TN-матрице взяли с запасом |
| Подсказка «Caps Lock включён» под полем (`getModifierState`) | снимает половину обращений «не подходит пароль» ещё до попытки входа |
| Кнопка-«глаз» в поле пароля | проверить ввод, не стирая его |
| Ссылки «Забыли пароль?» и «Инструкция по входу» под кнопкой | явный путь решения: `/help/login` (открыт без сессии, печатается на одном листе) |
| Заголовок и подписи — `font-semibold`, обычный трекинг, без CAPS-плаката | экран должен читаться как форма документа, а не как витрина |

### Вкладки персонала: док на телефоне, панель разделов на мониторе

`/librarian` и `/admin` рисуют навигацию одним компонентом
`src/components/ui/staff-tabs.tsx` — один список `TABS`, три вида:

| Экран | Как выглядит | Почему так |
| --- | --- | --- |
| < `sm` (телефон) | нижний док: «Скан» + 2–3 ежедневных раздела + «Ещё» (шторка с остальными) | ленты из 9 кнопок сверху нужно было скроллить пальцем и тянуться к ней через весь экран; док живёт в зоне большого пальца и всегда на месте |
| `sm`–`lg` (планшет) | липкая горизонтальная лента сверху | ширины хватает на все разделы в ряд, док только съел бы высоту списка |
| ≥ `lg` (монитор) | вертикальная панель слева (`sticky`), все разделы с подписями | на 1440px лента сверху — это «одна колонка посередине экрана»; панель слева освобождает ширину под двухколонник каталога |

* Счётчики прямо на кнопке («Долги 13», «Заявки 2») — `GET
  /api/staff/badges` (те же предикаты, что у списков: `Loan.status = ISSUED`,
  `BookRequest.status = PENDING`). Читаем при монтировании, при возврате
  вкладки на экран (`visibilitychange`) и после синхронизации офлайн-очереди
  (`DATA_CHANGED_EVENT`) — polling не нужен.
* «Скан» в доке открывает «Выдачу» и сразу включает камеру (nonce +
  `onScanConsumed`, чтобы возврат на вкладку камеру не включал). Посреди
  незавершённой выдачи не вмешивается.
* «Выдача» больше не размонтируется при переходе на другую вкладку
  (`hidden`, а не unmount): профиль с неотмеченными галочками раньше терялся
  от любого случайного тапа по доку.
* Стрелки `←/→/↑/↓`, `Home`, `End` переводят фокус по вкладкам; шторка «Ещё»
  блокирует прокрутку страницы за собой и закрывается по `Escape`/фону.

### Каталог и наборы: предпросмотр книги рядом со списком

Рабочее место библиотекар на мониторе (`?tab=catalog`) — двухколонник
`lg:grid-cols-[minmax(0,1fr)_22rem]`: слева списки (наборы сезона, свои
наборы), справа `sticky`-карточка выбранной книги. На телефоне та же
карточка открывается шторкой (`.sheet-in`), `Escape` и тап по фону закрывают.
Раньше карточка дорисовывалась ПОСЛЕ списка — чтобы её увидеть, нужно было
скроллить в конец страницы.

| Что | Где | Зачем |
| --- | --- | --- |
| `src/components/book-editor.tsx` | каталог библиотекаря + «Книги» в админке | обложка, название/предмет/ISBN, тираж, набор сезона, «кому на руках» и движения книги — в одном месте, правка без администратора |
| `PATCH /api/books/[id]`: `title`/`subject`/`isbn`/`copies`, любой сотрудник | `src/app/api/books/[id]/route.ts` | раньше можно было менять только тираж и только админу; опечатку в названии чинили удалением записи, что рвёт историю выдач. Удаление (`DELETE`) по-прежнему `adminGuard` |
| Отправка только изменённых полей | `book-editor.tsx` | правка названия не упирается в проверку тиража, если фонд уже «выдано больше, чем числится» |
| Чужой ISBN → `409` с названием книги-конкурента | `PATCH /api/books/[id]` | штрихкод в фонде уникален (`Book.isbn @unique`) |
| Превью у каждой строки (`BookCover`) | каталог, наборы, «Книги» в админке | список читается как полки, ошибиться строкой сложнее |
| Фильтр по строке, без запроса | `catalog-view.tsx`, `admin/panel.tsx` | каталог школы целиком уже в состоянии: сеть на каждое нажатие не нужна |
| Наборы: чипы + два стола («в наборе» и «добавить из каталога») + «Добавить в чек-листы классов» | `catalog-view.tsx` | собирать набор и назначать его параллели можно в одном экране, без перехода в «Классы» |

Знак библиотеки на `LogoMark` (`components/ui/logo-mark.tsx`) используется на
обоих экранах входа и в шапке главной; анимация (`.logo-tile`, `.logo-book`)
гасится в `prefers-reduced-motion` и в `data-perf="lean"`.

## 2. Скорость на слабом Android/iOS — конкретные правки

| Правка | Где | Эффект |
| --- | --- | --- |
| Убран `blur-3xl` «светящийся круг» с лендинга и `backdrop-blur` со sticky-шапок | `src/app/page.tsx`, `ui/page-header.tsx` | на Mali/Adreno 5хх размытие фона под липким слоем = перерисовка экрана на каждый кадр скролла |
| `content-visibility` на чек-листе выдачи, выборе ученика и «Долгах» (в «Журнале» приём уже был) | `librarian/issue-flow.tsx`, `debts-view.tsx` | список из 300 строк скроллится без лагов: раскладка считается только для видимого |
| Тени — статичные, по одной на карточку; hover-«подъём» убран | `ui/card.tsx`, `ui/button.tsx` | нет слоёв-сюрпризов при тапе |
| Переходы 100–150 мс, только `background-color/color/transform`; глобальное `prefers-reduced-motion` | `globals.css`, `ui/button.tsx` | меньше композитинга, уважение к системной настройке |
| Кнопка — `touch-manipulation` + `active:scale-[0.985]` | `ui/button.tsx` | отклик в тот же кадр, без 300-мс задержки двойного тапа |
| Обложки книг: `loading="lazy"`, `decoding="async"`, `fetchPriority="low"`, фикс. `width/height` | `components/book-cover.tsx` | каталог открывается по тексту; нет сдвига раскладки (CLS) при подгрузке |
| Камера: `fps` 10 → 6 (4 в лёгком режиме) + нативный `BarcodeDetector`, если он есть | `components/scanner.tsx` | декодирование штрихкода на железе Android; батарея и CPU не уходят в 100% |
| `aspect-ratio` блока виджета сканера | `components/scanner.tsx` | подсказка и кнопка «Готово» не прыгают после запуска камеры |
| `next build`: `optimizePackageImports: ["lucide-react"]`, `removeConsole` в проде | `next.config.ts` | иконки не тащатся в initial-бандл страниц |
| Нет веб-шрифтов и нет `Image`-оптимизации/картинок в UI | `globals.css` | минус 60–120 КБ и один сетевой раунд |
| Service Worker: офлайн-страница в precache, `cacheOnNavigation` | `next.config.ts` | «нет сети» в школьном здании = мгновенная заглушка, а не белый экран |

Итог по весу (проверено сборкой): **initial JS не вырос** — 436.9 → 436.4 КБ
(128.9 → 128.2 КБ gzip); CSS +1.1 КБ gzip на новые токены и утилиты.

## 3. PWA: установка и «родной» вид

`public/manifest.json`:

- `display_override: ["standalone","minimal-ui"]` — на Android приложение
  открывается без адресной строки; на iOS `display` работает только для
  «Домашнего экрана», поэтому там дублирует его `appleWebApp` из `layout.tsx`;
- иконки `any` + `maskable` (генерит `scripts/generate-icons.mjs`) — иначе
  Android вырезает круг из «обычной» иконки и книга обрезается;
- `apple-touch-icon.png` (180×180) — без него iOS берёт снимок страницы;
- `shortcuts` «Выдача» и «Долги» → `/librarian?tab=…`; вкладка читается из
  `?tab=` в `src/app/librarian/shell.tsx`, поэтому ярлык с рабочего стола
  открывает сразу нужный раздел;
- `theme_color`/`background_color` берутся из `THEME_COLORS`
  (`src/components/theme.tsx`) и синхронизируются с датой `data-theme`,
  поэтому статус-бар совпадает с фоном и в светлой, и в тёмной теме.

## 4. Проверка на Android (Chrome)

1. Открыть адрес на телефоне, меню ⋮ → «Установить приложение».
   Никаких флагов включать не нужно.
2. Для точных замеров подключить телефон кабелем и на ПК открыть
   `chrome://inspect` → inspect нужной вкладки.
3. Производительность: DevTools → Performance → запись 3–5 с прокрутки
   «Выдачи». Ориентиры: нет кадров длиннее ~32 мс в скролле и нет
   layout shift после загрузки (Rendering → Layout shift regions).
4. Офлайн-очередь: режим «в самолёте» → отметить книгу → включить сеть →
   плашка «N действий в очереди» должна смениться на «Синхронизировано».
5. Манифест: DevTools → Application → Manifest. Ожидаем 2 набора иконок
   (`any` + `maskable`), 2 shortcut'а, `display_override`.
   `installability errors` — пусто.

## 5. Проверка на iOS (Safari 17+)

1. «Поделиться» → «На экран „Домой“». Запускать **с** домашнего экрана:
   только там есть `display-mode: standalone` и safe-area.
2. Зум-ловушка: тап по любому полю не должен приближать страницу
   (16px в полях гарантируют `@supports (-webkit-touch-callout: none)` +
   `text-base` в `ui/input.tsx`). Проверить на «Пароль» и на дате в «Журнале».
3. Клавиатура: `interactiveWidget: "resizes-content"` → при открытой
   клавиатуре нижний док и кнопка «Выдать» остаются видимыми, страница не
   уезжает в бесконечный скролл.
4. Safe-area: повернуть телефон в ландшафт — текст не должен залезать под
   скругление экрана; на главном экране ученика нижняя панель QR не должна
   перекрываться полоской «Домой».
5. Тёмная тема: системная «Тёмная» → фон приложения `#03080a`, карточки
   `#080d0f`, статус-бар тот же цвет, что фон (это `THEME_COLORS` +
   `meta theme-color`); проверять, что карточка всё ещё отграничена от фона
   рамкой, — теней в тёмной теме нет.
6. Вибрация: на iOS `navigator.vibrate` недоступен — отметка выдачи просто
   не дрожит, ошибок в консоли быть не должно.

## 6. Быстрые self-проверки (вставить в консоль телефона)

ПК с подключённым телефоном (`chrome://inspect`) или «Показать консоль» в
Safari (Настройки → Safari → Консоль).

```js
// 1) safe-area действительно читается браузером:
const cs = getComputedStyle(document.documentElement);
console.log("safe areas", {
  t: cs.getPropertyValue("--sat") || "n/a",
  b: cs.getPropertyValue("--sab") || "n/a",
});

// 2) все тач-таргеты мельче 44px (должно быть пусто, кроме data-tight):
[...document.querySelectorAll("button,a[href],input,select,summary,[role=button]")]
  .filter((el) => {
    const r = el.getBoundingClientRect();
    return r.width > 0 && r.height > 0 && (r.height < 44 || r.width < 44) &&
      !el.closest("[data-tight]");
  })
  .forEach((el) => console.warn("мелкий таргет:", el.className, el.getBoundingClientRect().height));

// 3) поля, из-за которых iOS зумит (должно быть >= 16px):
[...document.querySelectorAll("input,select,textarea")]
  .filter((el) => parseFloat(getComputedStyle(el).fontSize) < 16)
  .forEach((el) => console.warn("поле < 16px:", el.name || el.placeholder));

// 4) есть ли горизонтальный оверфлоу (ползунки внизу экрана = баг вёрстки):
console.log("overflow-x:", document.documentElement.scrollWidth > window.innerWidth + 1);

// 5) включить ручной лёгкий режим вручную (для сравнения «на глаз»):
document.documentElement.dataset.perf = "lean";
```

## 7. Что осталось «на устройстве» (ограничения проверки)

- Песочница без GUI-браузера: реальные скриншоты приложения снять нельзя,
  поэтому визуальная часть проверена макетами 1:1 по токенам
  (`.design-preview/*.png`, генератор — там же) и сборкой; цифры по весу
  бандла — из `next build`.
- `fps`/нативный декодер камеры имеют смысл только на реальном телефоне с
  камерой; в эмуляторе камеры нет — там сканер покажет заглушку с ручной
  вводом кода (это тоже проверено и работает).
- iOS-клавиатура и `resizes-content`: если на конкретной версии Safari
  док всё же уедет под клавиатуру — поменять `interactiveWidget` в
  `src/app/layout.tsx` на `"unfocused"` (строка 1 файла с `viewport`).
